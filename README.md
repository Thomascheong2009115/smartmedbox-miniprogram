# 智能药箱 · 微信小程序大赛版

第四届微信小程序全球创新挑战赛澳门区域赛参赛项目，2026 年获一等奖（团体）。本版侧重微信小程序设计、用药管理与交互，以及 M10/K10 板端运行；参赛阶段未制作后续 IoT 版本的实体药箱。

后续制作实体原型、参加 IoT 比赛和澳门科学馆公开展示的版本，另见 [SmartMedBox IoT 版](https://github.com/Thomascheong2009115/smartmedbox-iot)。两版源于同一主题，分别记录，不将后续实体成果归入本版。

## 源码与版本

- `miniprogram/`：本次补充的小程序源码，含首页、药品管理、语音录入、历史记录、数据分析及通知页面。
- `supporting-python/`：同一补充文件夹中保存的板端和后端程序。文件包含部分硬件控制逻辑，不代表微信赛阶段已经制作实体；尚未核实每个文件的竞赛提交时点。
- `miniprogram/sub_lib/components/ec-canvas/`：原项目附带的 ECharts 及微信画布适配代码，保留原许可声明，未作为个人编写成果。

未上传本地编辑器配置、依赖安装目录、缓存或原始压缩包。原 AppID 已留空，默认服务地址改为本机地址。

张皓泓参与需求、功能与交互设计，使用 AI 生成代码并进行调试整合。代码不作为个人独立手写的证明；本仓库是比赛项目源码的后续整理。团队合作与后续 IoT 实体制作分开说明。

## 运行准备

1. 使用微信开发者工具导入 `miniprogram/`，填入自己的 AppID。
2. 在该目录执行 `npm ci`，然后在开发者工具中构建 npm。
3. 配置 `utils/config.js` 的 `BASE_URL` 及 `app.js` 的 `globalData.serverUrl`，指向自己的服务。正式设备调试还需配置微信平台要求的合法域名和 HTTPS。
4. `supporting-python/` 依赖相应板端、串口和后端运行环境，不能在普通电脑上直接完成硬件联调。

## 演示数据

`utils/mockData.js` 及 `utils/api.js` 含演示数据和接口失败时的回退逻辑；历史记录、分析和部分状态可能为演示内容。截图或界面统计不能作为实际用药、临床效果或硬件测量结果。原有“接口失败后返回成功”的演示行为也被保留，不能据此判断后端保存成功。

## 本次整理与验证

精简请求模块的重复与对话式注释，保留接口结构、错误处理与演示回退。补充后端的服务地址与密钥改为环境变量配置。可用 `node --test tests/request.test.cjs` 检查请求成功、404、服务器错误和网络失败的处理；`python tests/test_service_config.py` 检查缺少服务配置时不发起请求，以及使用指定地址的行为。已完成源码语法、JSON 配置和上述边界检查，尚未在微信开发者工具及真实设备上完成运行验证。

## 公开版本的服务配置

API 密钥、令牌及真实服务地址不随源码提供。后端从进程环境变量读取 `TENCENT_API_KEY`、`TENCENT_CHAT_URL`、`SILICONFLOW_API_KEY` 和 `SILICONFLOW_TRANSCRIPTION_URL`，默认均为空。需自行填入自己的配置，程序不会自动读取 `.env`。未配置相应密钥或地址时，相关云端功能返回未配置状态，不会向原服务地址发起请求。

板端与小程序保留本机回环地址作为开发占位；按自己的环境设置服务连接。公开归档不含本地私有配置、运行日志、上传文件和原始压缩包。依赖来源及开源许可链接保留。
